دليل ربط العروض المشتركة - INSSAT TRAVEL SERVICE
================================================

الهدف
-----
بعد إكمال الإعداد، تصبح العروض محفوظة في مستودع GitHub وتظهر لكل الزوار من أي هاتف أو كمبيوتر. GitHub يحفظ ملف العروض والصور، وCloudflare Worker يعمل كوسيط آمن بين الموقع وGitHub.

مهم قبل البدء
-------------
- لا تضع GitHub Token في index.html ولا ترسله في محادثة أو إلى الموظفين.
- لن تعمل الإدارة المشتركة قبل إكمال الخطوات أدناه ووضع رابط Worker الحقيقي في index.html.
- هذا النظام يتيح نشر/تعديل/حذف العروض، لكنه لا يغير صفحات Visa أو B2B أو صفحة العمرة المستقلة.

الخطوة 1: رفع ملفات الموقع إلى GitHub
-------------------------------------
1. فك ضغط الحزمة.
2. افتح مجلد INSSAT_TRAVEL_SERVICE_FINAL.
3. ارفع محتويات المجلد إلى جذر المستودع inssat-agence01 على الفرع main، مع استبدال index.html وإضافة مجلدي cloudflare-worker وdata.
4. تأكد أن GitHub Pages ما زال ينشر من main / (root).

الخطوة 2: إنشاء GitHub Token محدود
----------------------------------
1. من GitHub افتح Settings > Developer settings > Personal access tokens > Fine-grained tokens.
2. أنشئ Token جديداً باسم INSSAT Cloudflare Offers.
3. Repository access: اختر Only select repositories ثم inssat-agence01 فقط.
4. Repository permissions: اجعل Contents = Read and write. اترك باقي الصلاحيات دون منحها.
5. أنشئ الرمز وانسخه مؤقتاً إلى مكان آمن. لن يظهر كاملاً مرة أخرى.

الخطوة 3: إنشاء Cloudflare Worker
---------------------------------
1. أنشئ/سجّل الدخول إلى حساب Cloudflare.
2. افتح Workers & Pages ثم Create ثم Worker.
3. سمّه مثلاً inssat-offers-api وأنشئه.
4. افتح Edit code، واستبدل الكود الموجود بالكامل بمحتوى الملف:
   cloudflare-worker/worker.js
5. اضغط Deploy.
6. انسخ رابط Worker الذي ينتهي عادةً بـ workers.dev.

الخطوة 4: إعداد متغيرات Worker وأسراره
--------------------------------------
من Worker > Settings > Variables and Secrets أضف:

متغيرات نصية (Variables):
GH_OWNER       = inssat-travel
GH_REPO        = inssat-agence01
GH_BRANCH      = main
ALLOWED_ORIGIN = https://inssat-travel.github.io

أسرار (Secrets) - لا تضفها كمتغيرات عادية:
GH_TOKEN       = GitHub Fine-grained Token الذي أنشأته
ADMIN_PASSWORD = كلمة مرور قوية تختارها أنت ويستخدمها الموظفون المصرح لهم
SESSION_SECRET = سلسلة عشوائية طويلة جداً (يفضل 32 حرفاً أو أكثر)

احفظ التغييرات وأعد نشر Worker إذا طلب منك ذلك.
لا تستخدم كلمة مرور سهلة ولا تعِد استخدام كلمة مرور حساب GitHub.

الخطوة 5: ربط الموقع برابط Worker
---------------------------------
1. افتح index.html في مجلد الموقع.
2. ابحث عن السطر:
   const OFFERS_API = 'https://YOUR-WORKER-NAME.YOUR-SUBDOMAIN.workers.dev';
3. استبدل الرابط الوهمي برابط Worker الحقيقي الذي نسخته في الخطوة 3، مع الإبقاء على /offers و/login غير مضافين إلى الرابط.
4. احفظ الملف وارفع index.html المعدّل إلى جذر مستودع inssat-agence01 على main.

الخطوة 6: الاختبار
-----------------
1. افتح الموقع بعد اكتمال نشر GitHub Pages.
2. انتظر قليلاً حتى يصبح الموقع محدثاً.
3. اضغط «إضافة عرض» وسجّل الدخول بكلمة ADMIN_PASSWORD التي وضعتها في Cloudflare.
4. أضف عرضاً تجريبياً مع صورة صغيرة (أقل من 2 ميغابايت) ثم انشره.
5. افتح الموقع من هاتف آخر أو نافذة خاصة. يجب أن يظهر العرض للجميع.
6. جرّب التعديل والحذف بعد التأكد من نجاح النشر.

أماكن التخزين
-------------
- بيانات العروض: data/offers.json داخل GitHub.
- صور العروض: assets/offers/ داخل GitHub.
- لا تُخزّن العروض الجديدة في LocalStorage.

ملاحظات
-------
- أول عملية نشر قد تستغرق دقيقة أو أكثر حتى تظهر على GitHub Pages.
- إذا ظهر خطأ عند تسجيل الدخول، راجع ADMIN_PASSWORD وSESSION_SECRET ورابط Worker وALLOWED_ORIGIN.
- إذا ظهر خطأ عند الحفظ، تحقق من أن GitHub Token مرتبط بالمستودع الصحيح ويملك Contents: Read and write.
- أي عروض قديمة كانت محفوظة في LocalStorage على هاتف واحد لن تنتقل تلقائياً. أعد نشرها من لوحة الإدارة بعد ربط النظام.
- لا تشارك GitHub Token أو SESSION_SECRET مع أي موظف. الموظفون يحتاجون فقط كلمة مرور الإدارة.
